⚠️ 重要：テナント切り替えが必要（7/23定例での懸念点）

ゲストアクセス（B2B）の仕組み上、ゲスト側はアカウントを切り替えて参加する必要がある。
大学側参加者が指摘した通り「自分のアカウントでサインインしているTeamsから、招待されたテナントに切り替えて参照する」という操作が必要。これが煩雑さの原因。

⏱ 最終ログインから90日で自動失効（技術的実現可否）

技術的には可能。 Microsoft Entra ID Governance の「アクセスレビュー」機能を使い、最終サインインから指定日数（最大730日まで）でゲストアカウントを自動無効化・削除できる。

仕組み（2段階処理）

ステップ内容期間
① 不活性として検出最終サインインから90日経過したゲストをアクセスレビューが検出設定に基づき自動
② 無効化（アクセス剥奪）サインインをブロック。アカウントは残る。管理者が再有効化可能即時
③ 自動削除無効化から30日後にテナントからアカウントを完全削除無効化から30日後

「作成から90日」との違い

方式説明ユーザー体験
作成から90日（三井田当初案） 招待されてから90日で失効。毎回更新手続きが必要 アクティブユーザーも毎回更新が必要 → 煩雑
最終ログインから90日（大学側希望） 最後にサインインしてから90日間未使用で失効 使い続けている間は失効しない → ユーザーフレンドリー
⚠️ ライセンス要件：A3には含まれず、アドオン購入が必要
アクセスレビュー機能は Microsoft Entra ID Governance（旧 Azure AD P2 Identity Governance）が必要。A3 Educationライセンスには含まれていない。
必要アドオン: Microsoft Entra ID Governance P1 for Education（ゲストユーザー単位の課金）
2026年1月以降、ゲスト向けはアドオン購入が強制化されている。

設定箇所

  • Entra管理センター → Identity Governance → アクセスレビュー → 新規作成
  • 対象：ゲストユーザー
  • 頻度：四半期ごと（または任意の間隔）
  • 不活性閾値：90日（最大730日まで変更可）
  • 自動適用：「拒否されたゲストを無効化して削除」を有効化

代替案：追加ライセンスなしで管理する方法

方法内容管理者の手間ゲスト側の手間
① 作成から90日で自動失効
（標準機能・無料）		 Entra ID外部コラボレーション設定で「ゲストの有効期限を90日」に設定。期限が来ると招待リンクが無効になり、再招待が必要 少ない
自動で失効するため放置ゲストが残らない		 やや煩雑
継続利用の場合も90日ごとに再認証が必要
② 申請制 ＋ 台帳管理
（追加ライセンス不要）		 ゲスト招待は情シス承認制のまま。招待時に「氏名・目的・利用期間・担当者」を台帳（ExcelまたはTeamsチャネル）に記録。情シスが年2〜4回、台帳と実際のゲスト一覧を照合して不要なアカウントを手動削除 定期作業が必要
年2〜4回の手動レビュー（招待数が少なければ30分程度）		 少ない
有効期間中は操作不要
推奨：① ＋ ② の組み合わせ。 「作成から90日の自動失効」で放置アカウントを防ぎつつ、申請制と台帳管理で招待数そのものを絞る。ゲストアクセスの利用頻度が低いうちは、これが最もコストをかけずに管理できる現実的な方法。
